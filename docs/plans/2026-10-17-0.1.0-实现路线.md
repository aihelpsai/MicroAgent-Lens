## 1. 本路线的作用

本文件是 **0.1.0（MVP）的实现路线（Roadmap）**，只定四件事：分几个阶段、每阶段做什么、按什么顺序、怎么算做完。

它**不是**一份一次性全量执行的 plan。上下文有限，把全部模块塞进一份 plan 实现容易跑偏；因此按阶段切分，**每个阶段单独产一份细化 plan 后再实现**。阶段 plan 放 `docs/plans/`，命名 `YYYY-MM-DD-<阶段名>-plan.md`，一份实现完、验证通过、commit 后，再进下一阶段。

## 2. 目标与范围

**目标**：交付首个可用的控制型 Agent 调试器——`pip install -e .` 后一条 `lens serve` 起看板，agent 侧加 `@bind_tool` 装饰器即可获得「死循环熔断 + 高危工具断点 + trace 树回看」三项能力。

**版本**：包版本、文档、代号统一为 `0.1.0`（以 `pyproject.toml` 为准，PRD 亦定义 MVP = 0.1.0）。

**做（MVP 范围）**：

| 优先级 | 内容 | 落点 |
|---|---|---|
| 核心 | Active Guardrails：Loop Breaker（滑窗熔断）+ Active Breakpoint（人机断点） | `lens/server` 决策引擎 + 挂起机制 |
| 支撑 | 最小可用 Python SDK 探针（`@bind_tool` / `log_thought` / `AgentLoopException`） | `lens/sdk` |
| 展示 | 够用的控制面板（会话列表 + trace 树 + 断点配置 + 挂起弹框），暗黑高颜值是加分项 | `lens/webui` |
| 集成 | `lens serve` CLI + 端到端示例 | `lens/cli.py` + `examples/` |

**不做**：多租户、权限、生产高可用、团队共享、框架适配器（LangChain/LlamaIndex）、Go/TS SDK、LLM I/O 采集（llm 节点，协议已明确后置）、PyPI 发布（0.1.0 仅本地安装，打包验证见阶段 6）。

## 3. 架构与不变量对照

四条硬规则与阶段落点的映射（每阶段验收时逐条核对，review 用 `.claude/skills/review/` 清单）：

| 不变量 | 含义 | 落点 |
|---|---|---|
| 1 降级保证 | 看板未启动/不可达，SDK 静默降级、agent 照常跑 | 阶段 4（client 降级 + 装饰器不抛异常） |
| 2 智能放后端 | 熔断/断点/相似度全在 server；SDK 只「发 HTTP + 阻塞 + 抛异常/返回失败」 | 阶段 2（决策引擎纯函数）与阶段 4（薄 client）边界 |
| 3 统一决策端点 | 所有工具调用前只走 `POST /v1/execution-request` | 阶段 3（单端点两分支） |
| 4 语义区分 | 熔断→抛 `AgentLoopException`；断点【拒绝】→返回失败结果（不抛） | 阶段 4（装饰器三种响应分派） |

**目录终态**：

```
lens/
  __init__.py          # 公共 API 出口：bind_tool / log_thought / AgentLoopException
  cli.py               # lens serve 入口
  sdk/
    client.py          # 薄协议 client（httpx 同步）
    decorators.py      # bind_tool
    trace.py           # log_thought + contextvars 会话管理
    errors.py          # AgentLoopException
  server/
    app.py             # FastAPI 装配 + 8 端点 + StaticFiles 挂 webui
    loop_breaker.py    # 滑窗 + 相似度 + 熔断判定（纯函数）
    store.py           # SQLite 数据层
    decisions.py       # 挂起决策管理（pending + resolve 唤醒）
    stream.py          # WebSocket 内存 pub/sub
  webui/
    index.html         # 会话列表 + trace 树 + 断点面板 + 挂起弹框（单页）
openapi.yaml           # 契约唯一来源（实现只读不改，除非契约变更）
tests/                 # 每逻辑代码对应测试
examples/              # 端到端 demo agent
```

## 4. 阶段路线（6 个里程碑）

每个阶段 = 一份独立 plan + 一轮实现 + 一轮验证 + 一次 commit。阶段内子任务的粒度由该阶段的 plan 再细化，不在本路线展开。

### 阶段 1 — 项目框架

- **目标**：搭 `lens` 包骨架 + CLI 入口 + 最小可跑 FastAPI，跑通门禁基线。
- **交付物**：`lens/__init__.py`、`lens/cli.py`（`lens serve` 用 uvicorn 编程式启动 + argparse 标准库）、`lens/server/__init__.py` + `app.py`（最小 app）、`lens/sdk/__init__.py`、`lens/webui/index.html`（占位）、`tests/`（1 个 smoke）
- **进入条件**：无
- **退出判据**：`pip install -e ".[dev]"` 成功；`lens serve` 起服务、`curl -s localhost:7878/` 有响应；`ruff check .` / `mypy lens` / `pytest` 全绿

### 阶段 2 — server 决策引擎 + 数据层

- **目标**：熔断/断点判定纯同步函数 + SQLite 持久化（核心，砸力气）。
- **交付物**：`loop_breaker.py`（滑窗 window=3 + `difflib.SequenceMatcher.ratio()` 相似度阈值 0.9 + 熔断判定；args 先 `json.dumps(sort_keys=True)` 稳定序列化）、`breakpoint.py`（suspend 名单命中）、`store.py`（`sessions` / `trace_nodes` / `decisions` 三表 + 状态流转，标准库 `sqlite3`，每请求独立连接）
- **进入条件**：阶段 1
- **退出判据**：单测覆盖「连续 3 次同名同参触发熔断 / 参数不同不触发 / 窗口滑出不误判」+ 三表 CRUD + 状态流转；判定函数为纯函数（无全局状态）

### 阶段 3 — server HTTP API + 挂起 + WebSocket

- **目标**：8 端点逐字段对齐 `openapi.yaml` + 断点长挂机制 + 事件推送。
- **交付物**：`app.py`（8 端点）、`decisions.py`（pending 注册 + `asyncio.Future` 挂起 + resolve 唤醒）、`stream.py`（内存 pub/sub，五类事件）
- **进入条件**：阶段 2
- **退出判据**：TestClient 冒烟 8 端点字段与 schema 一致；并发测试「挂起不返回 → resolve(allow/reject) 返回对应结果」；WS 收到 `node_added` / `decision_pending` / `decision_resolved` / `loop_alert` / `session_status`

### 阶段 4 — SDK 探针

- **目标**：薄协议 client + 装饰器 + 降级 + 三语义。
- **交付物**：`client.py`（httpx 同步 5 个 POST，后端不可达时 `execution_request` 返回 allow、其余静默）、`errors.py`（`AgentLoopException` + `ToolRejected`）、`decorators.py`（`bind_tool`，含 `suspend` 参数）、`trace.py`（`log_thought` + contextvars 会话/父子管理）、`__init__.py` 导出三公共 API
- **进入条件**：阶段 1（契约 openapi 已有，可用 mock 先行；与阶段 3 并行，真联调在阶段 6）
- **退出判据**：降级测试（连不上不抛异常、返回 allow）+ 三语义测试（allow 执行 / reject:loop 抛 `AgentLoopException` / reject:human 抛 `ToolRejected` 专用非致命异常）

### 阶段 5 — WebUI

- **目标**：单页暗黑面板，原生 JS + 原生 WebSocket，零前端构建。
- **交付物**：`webui/index.html`（内联 JS/CSS）：会话列表、trace 树（Thought→Action→Observation）、断点配置面板（suspend 开关 + 熔断参数）、挂起弹框；`app.py` 挂 StaticFiles
- **进入条件**：阶段 3（需 API + WS）
- **退出判据**：`lens serve` 后浏览器：列表可见、trace 实时生长、命中 suspend 弹框、点放行/拒绝后 agent 继续；暗黑高颜值（加分项，不阻塞门禁）

### 阶段 6 — CLI 完善 + 端到端集成

- **目标**：`lens serve` 补全自动开浏览器 + 端到端示例 + 全量门禁收尾。
- **交付物**：`cli.py` 补全、`examples/` 自研 ReAct demo（普通 + suspend 工具）、端到端测试覆盖三场景、打包验证（`python -m build` 产出 wheel/sdist + 安装冒烟，不发布 PyPI）
- **进入条件**：阶段 3、4、5
- **退出判据**：三场景通过 + `ruff` / `mypy strict` / `pytest` 全量绿 + 手动跑 examples 演示

## 5. 关键实现决策（已确认）

| 决策点 | 方案 | 理由 |
|---|---|---|
| 挂起机制 | 后端 `async def` 端点 + `asyncio.Future` 挂起，`resolve` set_result 唤醒 | SDK 侧仍同步 httpx 阻塞（天然跨语言）；后端 async 仅为「延迟响应」服务，不违反「决策引擎纯同步」 |
| SQLite 访问 | 标准库 `sqlite3` + 简单锁，不引入 SQLAlchemy | 零依赖、本地单用户、够用 |
| 相似度算法 | `difflib.SequenceMatcher.ratio()`，阈值 0.9 | 标准库零依赖，`ratio()` 直接输出 [0,1] 相似度 |
| WebSocket 推送 | 后端内存 pub/sub（连接集合 + 广播） | 单进程本地工具，无需 Redis/MQ |
| 决策引擎形态 | 纯函数（滑窗历史作入参），SQLite 持久化除外 | 不变量「无全局可变状态」，易测 |
| suspend 声明 | `@bind_tool(suspend=True)` 由 SDK 在会话创建时合并进后端 `suspend_tools` 名单；后端名单为唯一决策源 | 决策仍在后端（不变量 2），装饰器参数只是「声明」非 SDK 侧判定（已确认） |
| token 展示 | MVP 列表页 `token_usage` 恒 0 或隐藏 | llm 节点采集协议已后置，无 LLM I/O 数据可算 |
| 版本号 | 包版本 / 文档 / 代号统一为 `0.1.0` | 单一事实来源 pyproject（已确认） |
| reject:human 语义 | 断点【拒绝】→ SDK 抛 `ToolRejected` 专用非致命异常（非 `AgentLoopException`），agent 捕获走错误分支 | 「不抛异常」实指「不终止 agent」；专用异常解决返回类型多样无法统一构造失败值（已确认） |
| args 序列化 | 相似度比较前 `json.dumps(args, sort_keys=True)` 稳定序列化 | dict key 顺序不稳定会导致熔断误判（已确认） |
| SQLite 并发 | store 每请求独立连接 | 避免 async 挂起端点与 sync 端点并发时的跨线程报错（已确认） |
| 打包 | 阶段 6 `python -m build` 产出 wheel/sdist + 安装冒烟，不发布 PyPI | 验证打包就绪但发布后置（已确认） |

## 6. 阶段依赖关系

```
阶段 1（框架）
  ├→ 阶段 2（决策引擎 + 数据层）
  │     └→ 阶段 3（API + 挂起 + WebSocket）──┐
  │                                          ├→ 阶段 5（WebUI）┐
  ├→ 阶段 4（SDK 探针，可 mock 与阶段 3 并行）──────────────────┤
  │                                                          ↓
  │                                           阶段 6（CLI + 端到端集成）
```

- **可并行点**：阶段 4（SDK，用 mock 测）与阶段 3（server）并行，真联调统一放阶段 6。
- **推进节奏**：一份阶段 plan → 实现 → 验证 → commit → 进下一阶段。每阶段独立成上下文，避免跨阶段跑偏。

## 7. 整体验收标准

**门禁（全部绿才算完成）**：

```bash
pip install -e ".[dev]"
ruff check .      # 0 error
mypy lens         # 0 error（strict）
pytest            # 全绿
```

**端到端三场景（examples/ 手动 + 集成测试双覆盖）**：

1. **降级**：不起看板直接跑 agent → 照常执行，无异常（不变量 1）。
2. **熔断**：起看板，agent 连续 3 次同名同参 → `reject:loop` → 抛 `AgentLoopException` 终止（不变量 3/4 前半）。
3. **断点**：`send_email` suspend → 命中挂起、网页弹框 → 放行继续 / 拒绝返回失败结果走错误分支（不变量 3/4 后半）。

## 8. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 挂起机制并发正确性（长挂 HTTP + resolve 唤醒） | 断点核心，做错人机协同失效 | 阶段 3 内专项并发测试，先于 webui 落地 |
| WebUI 原生 JS 手写交互复杂度高 | 拖慢展示层 | 展示层定位「够用」，暗黑是加分项非门槛；单页内联 |
| SDK 降级路径覆盖不全（连不上/超时/500） | 违反不变量 1，agent 崩溃 | 阶段 4 专项降级测试；review 清单第 1 条强制核对 |
| 协议实现与 openapi 漂移 | 跨语言契约失效 | review 清单第 2 条：改协议必须同步 openapi；实现只读不改契约 |

## 9. 工程评审产出（2026-10-17）

**What already exists**：无实现代码可复用（0 行）；协议契约 `openapi.yaml`、架构决策、PRD 均已定稿，本路线直接对齐，不重复建设。

**Failure modes（每条新 codepath 一个真实失败场景）**：

| codepath | 失败场景 | 测试 | 错误处理 | 用户可见 |
|---|---|---|---|---|
| SDK 降级（连不上/超时/500） | 看板未启动或挂了 | 阶段 4 降级测试 | 静默放行 | 无感知（符合不变量 1） |
| 挂起长 HTTP + resolve 唤醒 | 挂起期间 server 重启，pending 丢失 | 阶段 3 并发测试（不含重启恢复） | SDK 请求断开 | dev-time 可接受，MVP 不做恢复 |
