## 1. 目标与范围

把 `lens/webui/index.html` 从占位替换为真实单页暗黑面板：原生 JS + 原生 WebSocket，零前端构建。后端 `app.py` 已挂 `StaticFiles(directory=lens/webui, html=True)`，本阶段**只写这一个文件**，不动后端、不动 `openapi.yaml`。

**四功能（退出判据）**：会话列表可见、trace 树实时生长、命中 suspend 弹框、点放行/拒绝后 agent 继续。暗黑高颜值是加分项非门禁。

**交付物**：`lens/webui/index.html`（内联 `<style>` + `<script>` + `<body>` 结构）。

**不做**：改后端 / 改 openapi.yaml、前端决策逻辑（熔断/断点/相似度判定）、前端自动化测试（HTML/JS 不进 ruff/mypy/pytest 门禁）、CLI 补全 / 端到端示例（阶段 6）。

## 2. 设计决策

| # | 决策 | 方案 | 理由 / 来源 |
|---|---|---|---|
| D1 | 单文件内联 | `index.html` 内联全部 CSS/JS，**零外链**（不引 CDN/框架/npm） | 交接红线 2「零前端构建，倾向全内联零外链」 |
| D2 | WS URL 构造 | `(location.protocol === 'https:' ? 'wss://' : 'ws://') + location.host + '/v1/stream'` | 适配任意 host/端口，不写死 7878 |
| D3 | 前端状态模型 | JS 内存对象：`sessions[]`（列表）、`selectedId`（选中）、`trace[]`（选中会话节点）、`breakpoints`（配置）、`pendingDecisions`（Map：decision_id→decision，驱动弹框）、`ws` + `reconnectTimer` | 单页无框架，集中 state 便于渲染函数幂等重绘 |
| D4 | trace 扁平渲染 | `parent_id` 恒 null，按后端返回顺序（rowid/created_at）渲染，**不做层级连线**；三色区分 `thought` / `tool_call`(Action) / `tool_result`(Observation) | 交接已知坑 3「trace 扁平，按 created_at 顺序展示」 |
| D5 | 重连策略 | WS `onclose`/`onerror` → 固定间隔重试；`onopen` 后**全量回填**（GET sessions + 选中详情 + breakpoints） | 交接「前端断连后丢事件，重连后 GET 全量」；事件不重放 |
| D6 | 错误处理 | 非 2xx 读响应体 `error` 字段（**非** `detail`）；网络异常给状态栏/toast 提示，**不 crash**、不打断 WS | 交接已知坑 2「404 用 error 键」 |
| D7 | token 展示 | `token_usage` 恒 0 → 列表**隐藏** token 列 | 路线 §5「MVP token_usage 恒 0 或隐藏」 |
| D8 | PUT 断点语义 | 前端 PUT **恒同时携带** `suspend_tools` + `loop_breaker` | app.py：`suspend_tools` 省略=清空、`loop_breaker` 省略=回默认(3/0.9)；只传其一会误清/误重置 |
| D9 | 挂起弹框形态 | `pendingDecisions` Map 驱动，弹框内**逐条**列出（tool_name + 格式化 args + 放行/拒绝），支持并发多挂起；`decision_resolved` 移除对应项 | 并发 suspend 场景下不互相覆盖 |
| D10 | resolve 防重 | 点击放行/拒绝后该条按钮 `disabled`，直到 `decision_resolved` 移除 | 后端 `resolve` 幂等边界（已处理→404），前端兜底防连点 |
| D11 | loop_alert 展示 | 熔断告警走**非阻塞 toast**（不弹框），显示 session + tool_name | 熔断是即时 reject 无需人工操作，弹框会误导「需放行」 |
| D12 | 布局 | 三区 grid：`header`（标题+连接状态）／`aside`（会话列表）／`main`（trace 区 + 断点面板）；`modal` overlay + `toast` 容器；窄屏单列折叠 | 单页够用；暗黑主题用 `:root` CSS 变量统一 |
| D13 | 视觉优先级 | 先保四功能（列表/trace/弹框/resolve），再做暗黑打磨 | 交接红线 4「暗黑加分项非门禁」 |

## 3. 文件结构（单文件三段）

### 3.1 `<style>` — 暗黑设计系统

- `:root` CSS 变量：背景/面板/边框/文字/强调/三节点色/状态徽章色。
- 布局：grid 三区 + `modal`（fixed 遮罩）+ `toast`（右上浮层）。
- 组件：状态徽章（running 绿 / paused 琥珀 / ended 灰）、节点卡（三色左边框或图标 + 类型标签 + 内容区）、按钮（primary / danger / ghost）、输入框、标签、空态、loading。
- 响应式：`@media` 窄屏折叠为单列。

### 3.2 `<body>` — 静态结构（无逻辑）

- `header`：标题 `MicroAgent-Lens` + WS 连接状态点 + 健康提示。
- `aside`：会话列表容器（`ul`）。
- `main`：
  - `section#trace`：trace 节点列表容器（含空态/loading）。
  - `section#breakpoints`：断点配置面板（suspend_tools 增删输入 + `window_size` / `similarity_threshold` 数字输入 + 保存按钮）。
- `div#modal`：挂起决策弹框（列表 + 放行/拒绝按钮）。
- `div#toast`：toast 容器。

### 3.3 `<script>` — 逻辑（原生 JS）

- `api`：`request(method, path, body)` fetch 封装（统一读 `error` 键）+ `listSessions` / `getSession(id)` / `getBreakpoints` / `putBreakpoints(cfg)` / `resolveDecision(id, action)`。
- `ws`：`connect()` / 重连定时器 / `onmessage` 按 `event.type` 分发到五类 handler。
- `render`：`renderSessionList` / `renderTrace` / `renderBreakpoints` / `renderPendingModal` / `toast(msg)`，幂等重绘。
- 事件处理器：列表点击选中、断点表单提交、放行/拒绝点击。
- `init`：GET sessions + breakpoints → connect WS。

## 4. 前端消费契约（只读，来自交接 + app.py）

### 4.1 HTTP 端点

| 用途 | 方法+路径 | 响应关键字段 |
|---|---|---|
| 会话列表 | GET `/v1/sessions` | `{sessions:[{session_id,status,created_at,tool_count,token_usage}]}` |
| 会话详情 | GET `/v1/sessions/{id}` | `{session, trace:[TraceNode], pending_decisions:[DecisionSummary]}`；TraceNode `{node_id,type,parent_id,created_at,content}`（**无** session_id） |
| 断点读/写 | GET/PUT `/v1/breakpoints` | `{suspend_tools:[str], loop_breaker:{window_size,similarity_threshold}}` |
| 放行/拒绝 | POST `/v1/decisions/{id}/resolve` | body `{action:"allow"\|"reject"}` → `{decision,reason,decision_id}` |
| 健康 | GET `/health` | `{status:"ok"}` |

404 响应体 `{"error": str}`（**非** `detail`）。

### 4.2 WebSocket `/v1/stream` 五类事件（payload 字段名精确对齐）

| type | payload |
|---|---|
| `session_status` | `{type, session_id, status(running\|paused\|ended)}` |
| `node_added` | `{type, session_id, node:{node_id,type,parent_id,created_at,content,session_id}}`（node **含** session_id） |
| `decision_pending` | `{type, decision:{decision_id,session_id,tool_name,args,created_at}}` |
| `decision_resolved` | `{type, decision_id, decision(allow\|reject), reason(loop\|human\|null)}` |
| `loop_alert` | `{type, session_id, tool_name, args, decision_id, created_at}` |

**节点 content 按 type 变化**：`thought` → 字符串；`tool_call` → `{tool_name, args}`；`tool_result` → `{tool_name, ok, result, error, duration_ms}`。

### 6.2 浏览器手动验收四功能

起后端：`.venv/bin/lens serve`（默认 `127.0.0.1:7878`），浏览器开 `http://127.0.0.1:7878/`。

临时探针脚本（粘贴运行即可，**不落 `examples/`**，阶段 6 才建示例）：

```python
from lens import start_session, end_session, bind_tool, log_thought, ToolRejected

@bind_tool(suspend=True)
def send_email(recipient):
    return f"sent to {recipient}"

@bind_tool()
def fetch(url):
    return f"fetched {url}"

start_session()
log_thought("开始排查")
print(fetch("http://a"))          # allow → trace 生长 tool_call + tool_result
try:
    send_email("a@b.c")            # 命中 suspend → 弹框 → 放行返回 / 拒绝抛 ToolRejected
except ToolRejected as e:
    print("被拒绝:", e)
end_session()
```

| 功能 | 步骤 | 通过判据 |
|---|---|---|
| 列表可见 | 跑脚本 → 看板 | 会话出现，状态徽章 running/paused/ended 随流转变化 |
| trace 实时 | 脚本逐工具执行 | `thought`/`tool_call`/`tool_result` 节点按序实时追加，三色区分 |
| 断点配置 | 面板增删 suspend_tools / 改熔断参数 → 保存 | 后端 `GET /v1/breakpoints` 确认更新；刷新回显 |
| suspend 弹框 | `send_email` 命中 | 弹框显示 tool_name+args；点「放行」脚本继续、点「拒绝」抛 `ToolRejected`；`decision_resolved` 关框、会话恢复 running |

## 7. 红线（勿越界）

1. **智能放后端**：前端只展示 + 发 `resolve` / `breakpoints` 请求，**不做**熔断/断点/相似度判定。
2. **零前端构建**：原生 JS + 原生 WebSocket，单文件内联，零外链，不引框架/npm/CDN。
3. **不改 openapi.yaml / 不改 `lens/server/app.py` / 不改任何 server、sdk 模块**；发现契约缺陷先提出来问，不自行改后端。
4. **不做 CLI 补全 / 端到端示例**（阶段 6）。
5. **不用 worktree、不强制 formal review**，直接 main 分支实现（延续阶段 1 决策 1/3）。
6. **不新增依赖**。

## 8. 已知坑（实现时必读）

1. **`decision_resolved` 结果字段叫 `decision`**（`allow|reject`），不是 `action`/`outcome`——与 HTTP resolve 请求体 `action` 不同，前端解析别混。
2. **404 用 `error` 键**（非 `detail`）：错误提示读 `resp.error`。
3. **trace 扁平**：`parent_id` 恒 null，按顺序渲染，别等层级数据（会一直空）。
4. **HTTP trace node 无 `session_id`；WS `node_added` 的 node 含 `session_id`**（全局流按会话归组），前端渲染不依赖 node.session_id。
5. **PUT `/v1/breakpoints` 覆盖/重置语义**：`suspend_tools` 省略=清空、`loop_breaker` 省略=回默认(3/0.9)，前端必须恒同时携带两字段（D8）。
6. **`.venv` 前缀**：无 `python` 命令；起后端 `.venv/bin/lens serve`。
7. **手动验收**：阶段 5 无自动化前端测试，门禁只看存量 pytest 不破；四功能靠浏览器人工走查。
