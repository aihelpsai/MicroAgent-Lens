## 2. 关键实现决策（本阶段新增，与路线 §5 不冲突）

1. **`create_app(db_path) -> FastAPI` 工厂 + 无模块级 `app`**。阶段 1 的 `app.py` 只有模块级 `app`，无法注入隔离 db。改为工厂：`Store(db_path).init()` → 挂 `app.state.store` / `.decisions` / `.hub` / `.breakpoints` → 注册路由。`cli.py` 的 `_serve` 改调 `create_app(_default_db_path())`。模块级 `app` 移除，测试全部走 `create_app(tmp_path/"x.db")` 拿隔离实例。
2. **默认 db 路径 `~/.lens/lens.db`**（`Path.home()/".lens"/"lens.db"`），`create_app` 内 `mkdir(parents=True, exist_ok=True)` 后 `Store.init()`。零配置、跨重启保留会话。
3. **断点配置内存态（不落 SQLite）**：`suspend_tools` + `loop_breaker{window_size, similarity_threshold}` 存 `app.state.breakpoints`（`dataclass`），GET/PUT 读写。openapi 无断点表、store 无断点表，故不持久化；重启回默认值（`suspend_tools=[]`、`window_size=3`、`threshold=0.9`），dev-time 可接受。
4. **suspend_tools 唯一来源 = PUT /v1/breakpoints（本阶段）**。路线 §5「SDK 在会话创建时合并进 suspend_tools」属阶段 4（装饰器声明），通道待定（大概率走 `POST /v1/sessions` 的 `metadata.suspend_tools` 自由字段，无需改 openapi）。本阶段**不**实现该合并，`POST /v1/sessions` 的 `metadata` 仅原样存取。
5. **loop breaker 历史源 = `trace_nodes(type='tool_call')`**。每次 `execution-request` 都先写一条 `tool_call` trace 节点（`content={"tool_name":..., "args":...}`），既是 trace 树的 Action 节点、又是熔断历史。读历史复用 `store.list_nodes(session_id)` 在端点内过滤 `type=='tool_call'` 取末尾 `window_size-1` 条，**不改 store**。
6. **decision 行只在「可行动」结果时落库**：挂起→`pending`、熔断→`rejected(reason=loop)`；`allow` 不落 decision 行（无后续 resolve 需求），但 `ExecutionResponse.decision_id` 是必填字段 → allow 也生成一个 `uuid4` 返回（不持久化）。挂起 resolve 后由 resolve 端点 `transition_decision`。
7. **判定顺序 = design §核心语义 1**：① `should_break` 熔断 → ② `is_suspended` 挂起 → ③ allow。熔断优先于挂起（同名同参同时命中时熔断立即拒）。**推论**：suspend 名单内的工具连续 3 次同参调用也会在第 3 次触发熔断（熔断历史含被拒的挂起调用）——这是预期行为，agent 反复同参即死循环，熔断优于反复人工确认。
8. **挂起 = 后端 `async def` 端点 + `asyncio.Future`**（路线 §5 已确认）。`execution-request` 命中 suspend 时 `create_decision(pending)` + `set_session_status('paused')` + 写 tool_call 节点 + 广播 `decision_pending`，然后 `await` 由 `decisions.py` 注册的 Future；resolve 端点 `transition_decision` + `set_result` 唤醒。
9. **resolve 端点返回 `ExecutionResponse`**（openapi 已定）：`action=allow` → `{decision:"allow", reason:null}`；`action=reject` → `{decision:"reject", reason:"human"}`。挂起的 `execution-request` 被唤醒后按 Future 结果返回同构响应。
10. **session 状态恢复**：resolve 后 `transition_decision` 使该 decision 离开 pending，随后 `list_pending_decisions(session_id)` 若空才 `set_session_status('running')`，否则保持 `paused`（多 pending 并发下不提前解锁）。
11. **404 响应体用 `{"error": str}`**（openapi `NotFound` 是 `error` 键，非 FastAPI 默认 `detail`）：写 `_not_found(msg)` 返回 `JSONResponse(404, {"error": ...})`，不用 `HTTPException`。
12. **请求体用 pydantic 模型、响应体用手工 dict**。请求模型（`ExecutionRequest` / `ToolResult` / `Thought` / `SessionCreate` / `BreakpointConfigUpdate` / `ResolveRequest`）内联在 `app.py`，镜像 openapi schema 做校验；响应用 `_xxx_dict(...)` 序列化 helper 从 store 冻结 dataclass 手工构造，键名逐字对齐 openapi（含 `reason: None` 显式 null、`token_usage: 0` 补齐）。
13. **end 时遗留 pending 的处理**（已确认：处理）：正常 SDK 流程中「有 pending」即 SDK 正阻塞在 `execution-request`，不可能同时调 `end`，故该场景只会由 WebUI 人为触发。`end_session` 先把该会话所有 pending 逐个 `transition_decision(rejected, reason=human)` + `decisions.resolve(did, "reject")` 唤醒 SDK，再置 `ended`（~5 行），避免挂起请求永久阻塞。

## 3. 模块设计

### 3.1 `decisions.py` — 挂起决策注册表（纯内存）

```python
DecisionOutcome = Literal["allow", "reject"]

class DecisionRegistry:
    def __init__(self) -> None:
        self._pending: dict[str, asyncio.Future[DecisionOutcome]] = {}

    def register(self, decision_id: str) -> asyncio.Future[DecisionOutcome]:
        # 在 async 端点内调用；asyncio.get_running_loop().create_future()
        future = asyncio.get_running_loop().create_future()
        self._pending[decision_id] = future
        return future

    def resolve(self, decision_id: str, outcome: DecisionOutcome) -> bool:
        # 取出并 set_result；不存在/已 resolved → False（端点映射 404）
        future = self._pending.pop(decision_id, None)
        if future is None or future.done():
            return False
        future.set_result(outcome)
        return True

    def is_pending(self, decision_id: str) -> bool:
        return decision_id in self._pending
```

- 单事件循环内访问，无需锁；内存态，重启丢失（路线 §9 已确认接受）。
- `DecisionOutcome` 只载 `allow`/`reject`（挂起唤醒后的最终决策），`reason` 由唤醒后的端点按 outcome 推导（reject→human）。

### 3.2 `stream.py` — 内存 pub/sub

```python
class _Sender(Protocol):                       # 解耦真实 WebSocket，便于单测
    async def send_json(self, data: Any) -> None: ...

class StreamHub:
    def __init__(self) -> None:
        self._connections: set[_Sender] = set()
        self._lock = asyncio.Lock()            # 并发广播互斥

    async def connect(self, ws: _Sender) -> None:
        await ws.accept()
        self._connections.add(ws)

    def disconnect(self, ws: _Sender) -> None:
        self._connections.discard(ws)

    async def broadcast(self, event: dict[str, Any]) -> None:
        async with self._lock:
            for ws in list(self._connections):
                try:
                    await ws.send_json(event)
                except Exception:
                    self._connections.discard(ws)   # 死连接即时剔除
```

WS 端点（`app.py` 内）：

```python
@app.websocket("/v1/stream")
async def stream(ws: WebSocket) -> None:
    hub = cast(StreamHub, ws.app.state.hub)
    await hub.connect(ws)
    try:
        while True:
            await ws.receive_text()          # 占位心跳；断开即抛 WebSocketDisconnect
    except WebSocketDisconnect:
        hub.disconnect(ws)
```

### 3.3 五类 WS 事件契约（WS-only，`docs/design` 为源，非 openapi）

| type | payload | 触发端点 |
|---|---|---|
| `node_added` | `{"type":"node_added","session_id":str,"node":{node_id,type,parent_id,created_at,content}}` | thought / tool-result / execution-request 写 tool_call 节点后 |
| `decision_pending` | `{"type":"decision_pending","decision":{decision_id,session_id,tool_name,args,created_at}}` | execution-request 命中挂起 |
| `decision_resolved` | `{"type":"decision_resolved","decision_id":str,"decision":"allow"\|"reject","reason":"human"\|null}` | resolve 端点 |
| `loop_alert` | `{"type":"loop_alert","session_id":str,"tool_name":str,"args":obj,"decision_id":str,"created_at":str}` | execution-request 熔断 |
| `session_status` | `{"type":"session_status","session_id":str,"status":"running"\|"paused"\|"ended"}` | 创建 / 挂起 / resolve 恢复 / 结束 |

> 注：`node_added` 的 `node` 含 `session_id`（WS 全局流，前端需按会话归组），区别于 HTTP `trace` 数组里的节点（openapi `TraceNode` 无 session_id）。

### 3.4 store 复用清单（零改动，全部已具备）

| 用途 | 调用 | 说明 |
|---|---|---|
| 建会话 | `create_session(session_id, metadata)` | 阶段 3 由端点生成 `uuid4` |
| 查/列会话 | `get_session` / `list_sessions` | `list_sessions` 已含 `tool_count` |
| 结束 | `set_session_status(sid, "ended")` | 终态 |

### 3.5 `create_app` 装配骨架

```python
@dataclass
class BreakpointConfig:
    suspend_tools: list[str] = field(default_factory=list)
    window_size: int = 3
    similarity_threshold: float = 0.9

def _default_db_path() -> Path:
    return Path.home() / ".lens" / "lens.db"

def create_app(db_path: str | Path) -> FastAPI:
    path = Path(db_path)
    path.parent.mkdir(parents=True, exist_ok=True)
    store = Store(path); store.init()
    app = FastAPI(title="microagent-lens", version="0.1.0")
    app.state.store = store
    app.state.decisions = DecisionRegistry()
    app.state.hub = StreamHub()
    app.state.breakpoints = BreakpointConfig()
    _register_routes(app)
    # 静态挂载位：最后挂 StaticFiles(html=True) 到 "/"，服务 lens/webui/index.html 占位
    return app
```

`app.state` 为 `Any`，端点内用 `cast(Store, request.app.state.store)` 取回（mypy strict）。

### 4.1 `POST /v1/execution-request`（核心，长挂）

```
store.get_session(sid) 为 None → 404
status == "ended" → 404（防状态机 ValueError 泄漏为 500）
recent = [ToolCall(tool_name, args) for n in list_nodes(sid) if n.type=="tool_call"][-(window-1):]
  # content 为 {"tool_name":..., "args":...}，cast 取回
current = ToolCall(tool_name, args)

① should_break(recent, current, window_size, threshold):
   did = uuid4()
   create_decision(did, sid, tool_name, args, status="rejected", reason="loop")
   add_node(uuid4(), sid, "tool_call", {"tool_name":tool_name,"args":args})
   广播 loop_alert + node_added
   return {"decision":"reject","reason":"loop","decision_id":did}

② is_suspended(tool_name, suspend_tools):
   did = uuid4()
   create_decision(did, sid, tool_name, args, status="pending")
   add_node(uuid4(), sid, "tool_call", {"tool_name":tool_name,"args":args})
   set_session_status(sid, "paused")
   广播 node_added + decision_pending + session_status(paused)
   outcome = await decisions.register(did)          # 长挂
   if outcome == "allow":
       return {"decision":"allow","reason":None,"decision_id":did}
   return {"decision":"reject","reason":"human","decision_id":did}

③ else:
   add_node(uuid4(), sid, "tool_call", {"tool_name":tool_name,"args":args})
   广播 node_added
   return {"decision":"allow","reason":None,"decision_id":uuid4()}
```

### 4.2 `POST /v1/decisions/{did}/resolve`

```
decision = store.get_decision(did) 为 None → 404
decision.status != "pending" → 404        # 已 resolved（重复 resolve 也 404）
store.transition_decision(did, "allowed" 或 "rejected", reason=("human" if reject else None))
if not store.list_pending_decisions(decision.session_id):
    set_session_status(decision.session_id, "running")
decisions.resolve(did, action)            # 唤醒挂起的 execution-request（返回值仅防御，忽略）
广播 decision_resolved + session_status
return ExecutionResponse：
  allow → {"decision":"allow","reason":None,"decision_id":did}
  reject → {"decision":"reject","reason":"human","decision_id":did}
```

> **404 依据是 DB 的 decision 状态（`status != "pending"`），不是 registry 返回值**：重启后 registry 可能丢 Future 而 DB 残留 pending 行，此时仍应落库 transition + 返回 200（清掉残留 pending），而非 404。顺序固定：先落库（transition）→ 再恢复 session → 再唤醒（`decisions.resolve`）→ 最后广播；落库先于唤醒，保证 SDK 醒来看得到一致状态。

## 5. mypy strict 已知坑（沿用阶段 1/2）

- `app.state.*` 为 `Any`：统一 `cast(Store, request.app.state.store)`（`decisions`/`hub`/`breakpoints` 同理）。
- `list_nodes` 返回 `TraceNode.content` 为 `Any`：取 tool_call 的 `content["tool_name"]` / `content["args"]` 需 `cast(dict[str, Any], n.content)`。
- `json` 出入与 sqlite 行取值 `Any` 的 cast 沿用阶段 2；时间戳 `datetime.now(UTC).isoformat()`（ruff UP017）。
- sqlite3 legacy 模式：**端点内若直接碰 sqlite3 写操作必须显式 `conn.commit()`**；但本阶段端点**不直接碰 sqlite3**，全部走 `Store`（store 已自 commit）。
- `asyncio.Future[DecisionOutcome]` 泛型注解；`asyncio.get_running_loop()` 只在 async 上下文调用。
- 所有 `async def` 端点带完整返回注解（`-> dict[str, Any]` / `-> None`）。
