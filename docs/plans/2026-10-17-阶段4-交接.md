## SDK 的协议来源（重要）

SDK 只读 `openapi.yaml`，**不 import、不读 `lens/server/` 任何实现**（不变量 2 的边界：server 是后端内部，SDK 与它是 HTTP 契约关系）。SDK 用到的端点与响应字段：

- `POST /v1/sessions`（body 可选 `{metadata}`）→ 200 返回 `Session{session_id,status,created_at,ended_at,metadata}`
- `POST /v1/execution-request`（body `{session_id,tool_name,args}`）→ 200 返回 `ExecutionResponse{decision(allow|reject), reason(loop|human|null), decision_id}`；**可能长挂起**（后端 async 端点挂 Future，SDK 同步 httpx 阻塞等响应即可）；404 返回 `{error}`。
- `POST /v1/tool-result`（body `{session_id,tool_name,ok,result?,error?,duration_ms?}`）→ 200 空对象
- `POST /v1/thought`（body `{session_id,content}`）→ 200 空对象
- `POST /v1/sessions/{session_id}/end` → 200 返回 `Session`
- `GET /v1/breakpoints` → `{suspend_tools:[...], loop_breaker:{window_size,similarity_threshold}}`
- `PUT /v1/breakpoints`（body 同上 schema）→ 200 返回配置

## 否决类决策（红线，阶段 4 勿重犯）

1. **SDK 禁止决策逻辑**（不变量 2，最硬）：熔断/断点/相似度/滑窗判定全在 server。SDK 只「发 HTTP + 阻塞等响应 + 按响应分派」。**禁止** import `lens.server` 的任何判定函数、禁止在 SDK 里自己数「第 3 次同名同参」或自己判断是否 suspend——SDK 的 suspend 参数只是「声明」并合并进后端名单，判定仍由后端做。
2. **三语义分派**（不变量 4）：`reject:loop` → 抛 `AgentLoopException`（终止 agent）；`reject:human` → 抛 `ToolRejected`（专用非致命异常，agent 捕获走错误分支）；`allow` → 正常执行。**别把 reject:human 也抛成 AgentLoopException**，别把熔断做成「返回失败值」。
3. **降级**（不变量 1）：连不上 / 超时 / 5xx 时，`execution_request` 返回 allow（放行）、其余端点（create_session / tool-result / thought / end / breakpoints）静默不抛。SDK 永不因后端不可达而让 agent 崩溃。
4. **suspend 声明合并 = SDK 侧读改写，后端不加 merge 端点**：阶段 3 的 `PUT /v1/breakpoints` 是「提供则覆盖、否则清空」语义（无 merge）。`@bind_tool(suspend=True)` 要把工具名并进后端 `suspend_tools`，就在 **SDK 侧**做「GET 现有名单 → 并集 → PUT」，别改后端端点加 merge。若认为必须后端加 merge，先提出来问用户，别自行扩。
5. **同步优先**：SDK 用同步 `httpx.Client`，无 asyncio / asyncio.Event / WebSocket。后端长挂，SDK 阻塞等响应即是正确行为（这也是设计：后端 async 仅为「延迟响应」服务）。
6. **零新依赖**：httpx 0.28 已装，同步可用；降级测试用 `httpx.MockTransport`（内置）或直连真实 server，别新增 requests / aioresponses 等。
7. **不强制 formal review、不用 git worktree**（延续阶段 1 决策 1/3）：直接 main 分支实现；plan 产出后是否走 gstack-plan-eng-review 由用户定。

## 已知坑（阶段 1/2/3 实测，阶段 4 必读）

1. **httpx 0.28 已装**：`httpx.Client`（同步）+ `httpx.MockTransport`（降级测试）都可用，无需新装。注意阶段 4 起 SDK 用同步 client，与阶段 3 测试用 async client 不同。
2. **环境命令用 `.venv` 前缀**：本机无 `python` 命令，用 `.venv/bin/python` / `.venv/bin/ruff` / `.venv/bin/mypy` / `.venv/bin/pytest`。
3. **mypy strict 坑**：`cast()`、`dict[str, Any]`（disallow_any_generics 禁裸 `dict`）、每个函数返回值显式注解（含 `-> None`）。SDK 解析 JSON 响应时 `resp.json()` 返回 `Any`，字段取值需 `cast`。
4. **datetime.UTC 而非 timezone.utc**：ruff UP017 强制。SDK 多数场景不生成时间戳（后端生成 created_at），若生成用 `datetime.now(UTC)`。
5. **StarletteDeprecationWarning**：已知可忽略，勿改 pyproject。
6. **阶段 3 已完成，SDK 可直连真实 server 联调三语义**：路线 §6 原设计阶段 4 与阶段 3 并行、用 mock 测。既然阶段 3 已完成，SDK 的三语义/降级测试可直接连真实后端（起 server 或 TestClient ASGI），比 mock 更扎实，是加分项非硬要求；但端到端三场景演示（不起看板跑 agent / 熔断终止 / 断点弹框）仍留阶段 6。
