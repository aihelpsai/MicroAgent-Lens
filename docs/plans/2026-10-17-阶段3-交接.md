## 否决类决策（红线，下阶段勿重犯）

1. **store 不实现 delete**：openapi 无 DELETE 端点、阶段 3 端点也用不到（会话结束=改状态、决策=改状态、trace 只增不删），纯「预留」，砍掉。阶段 3 若想要「清空会话」先问用户，别自行加。
2. **args 序列化只排顶层 key**：`json.dumps(args, sort_keys=True)` 只排顶层，嵌套 dict key 顺序不保证稳定——已确认边界，MVP 不递归排序，阶段 3 勿「顺手」补递归（扩 scope）。
3. **状态机落 Python 层**：`Literal` 类型别名 + 显式合法流转表 + 非法抛 `ValueError`，不引 `enum`/`StrEnum`。session `running→paused→running→ended`（ended 终态）；decision `pending→allowed/rejected`（reason 仅 rejected 带 loop/human）；同状态幂等 no-op。
4. **Store 每方法独立连接**：`Store.__init__` 只持不可变 `db_path`，每方法 `with closing(sqlite3.connect(...))` 开独立连接，无持久连接字段。阶段 3 别把连接提升为实例属性（会破坏并发安全）。
5. **不强制 formal review**（延续阶段 1 决策 3）：阶段 3 plan 产出后是否走 gstack-plan-eng-review 由用户按需定。
6. **不用 git worktree**（延续阶段 1 决策 1）：直接 main 分支实现，勿 `EnterWorktree`。

## 已知坑（本阶段实测，阶段 3 必读）

1. **sqlite3 legacy 模式：写方法必须显式 `conn.commit()`**（最关键）。本机 Python 3.13 sqlite3 默认 `isolation_level=""`（legacy），`closing(conn)` 关闭时**未提交的 INSERT/UPDATE/DELETE 会被回滚**，只有 DDL 隐式持久化。store 每个写方法末尾都显式 `conn.commit()`。阶段 3 若在 store 加新写方法、或端点内直接碰 sqlite3，写操作末尾漏 commit 会导致「create 后 get 查不到」——已用最小重现确认，这是最容易踩且最难一眼看出的坑。
2. **时间戳用 `datetime.UTC` 而非 `timezone.utc`**：ruff UP017 强制要求（Python 3.11+ 支持），写 `datetime.now(UTC).isoformat()`。阶段 1/2 的 argparse cast、json.loads/sqlite3 行取值 `Any` 需 `cast` 的 mypy strict 坑同样沿用。
3. **StarletteDeprecationWarning**：fastapi 0.143 + starlette 1.8 的 TestClient 告警「httpx 弃用、装 httpx2」。阶段 3 用 TestClient 测 8 端点会刷屏，届时评估是否改依赖；**勿提前改 pyproject**（阶段 2 已明确，延续）。
4. **环境命令用 `.venv` 前缀**：本机无 `python` 命令，用 `.venv/bin/python` / `.venv/bin/ruff` / `.venv/bin/mypy` / `.venv/bin/pytest`，或先 `source .venv/bin/activate`。依赖已装（fastapi 0.143 / uvicorn 0.54 / httpx 0.28 / mypy 2.4 / ruff 0.17 / pytest 9.1 / starlette 1.8）。
