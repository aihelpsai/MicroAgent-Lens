# Code Review 清单

审查本仓库代码改动时，逐条检查；命中任一条即要求修改。审查结论需逐条给出"通过 / 不通过 + 理由"。

## 1. 架构不变量（最优先）

- **降级保证**：看板未启动/不可达时，SDK 是否仍静默降级、agent 照常运行？改动是否破坏该保证？
- **智能放后端**：是否把决策逻辑（熔断判定 / 断点决策 / 相似度计算）放进了 SDK？SDK 只能"发 HTTP + 阻塞 + 抛异常/返回失败"。
- **统一决策端点**：是否新增了绕过 `POST /v1/execution-request` 的工具调用路径？
- **语义区分**：熔断是否抛 `AgentLoopException`？断点【拒绝】是否返回失败结果而非抛异常？

## 2. 协议契约

- 是否改动协议（endpoint / JSON schema）？→ 必须同步更新根目录 `openapi.yaml` 并评估跨语言影响。
- 契约唯一来源：代码里不得另写一份对不齐的 schema。

## 3. 代码实现约定

- **同步/异步**：SDK 是否用同步阻塞（无 asyncio.Event / WebSocket）？
- **异常**：降级路径是否静默（不抛异常）？
- **全局状态**：决策引擎是否纯函数、无全局可变状态？
- **命名/类型**：是否过 ruff N 规则与 mypy strict（门禁自动查，review 只需确认跑过）。

## 4. 验证判据

- 这次改动的判据是什么（跑什么命令、看什么输出）？是否跑过 `ruff check` / `mypy lens` / `pytest`？
- 架构不变量对应的测试是否仍绿？
- 新增逻辑代码是否带了对应测试脚本？

## 5. 依赖与范围

- 是否新增依赖？必要吗？是否记入 `docs/decisions/`？
- 是否超出任务范围（drive-by）？超出部分应拆分或删除。
